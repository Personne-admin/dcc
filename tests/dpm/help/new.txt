usage: dpm new [DIR] [options]

Generates a project in DIR (default: the current directory, which must be
empty) from a template and prints what to do next. Without --template the
built-in executable template is used, or the library template with --lib. The
template is a directory (path:DIR, ./DIR or /DIR), a git location
(github.com/user/repo[/subdir], git+https://host/repo.git[#subdir], optionally
followed by @version) or an https .tar.gz. A fetched template is checked like
a dependency, cached by tree hash, and its commit and hash are printed. A
template is data: nothing in it is run. The project is written into a
temporary directory first and moved into place only when everything succeeded.

options:
  --template <source>       generate the project from this template. A
                            built-in template (builtin:executable,
                            builtin:library) or a directory that holds a
                            template.dcon. [default: builtin:executable]
  --set <var>=<value>       give a template variable a value. May be repeated.
                            'dpm template info <source>' lists the variables.
                            --name is the same as --set name=<name>.
  --lib                     create a library (src/<name>/lib.dc) instead of an
                            executable
  --name <name>             name to use instead of the directory name
  --ref <ref>               fetch this branch, tag or full commit id of a git
                            template. Without it the latest v<version> tag is
                            used, or the tag named by <source>@<version>. A
                            repository without version tags needs --ref.
  --pin <hash>              require the fetched template to have this tree
                            hash. The hash is printed by every fetch
                            ('sha256:' and 64 hex digits). A mismatch is an
                            integrity error (exit code 4) and nothing is
                            generated.
  --offline                 never use the network; use only what is in the
                            cache. The same as DPM_OFFLINE=1. Something that
                            is missing from the cache is an error (exit code
                            5).

exit codes:
  0                         success
  1                         a build or test failed, a precondition was not
                            met, or a file could not be written
  2                         usage error
  3                         invalid manifest, lock or configuration file
  4                         resolution or integrity error (conflicting
                            versions, hash mismatch, registry problems)
  5                         network error, or something is missing from the
                            cache while offline
